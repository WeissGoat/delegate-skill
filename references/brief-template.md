# Brief 模板

复制后填写。worker 只看得到这份 brief 和规则，看不到你和用户的对话。

```markdown
任务：<一句话目标，例如：用命令口走查最新的打包版，检查一次完整下潜中有没有界面遮挡或卡住。>

背景（只写 worker 判断需要的）：
- <例如：构建目录是 Builds/Windows/P3_20261016_2340，已跳过序章。>

步骤：
1. `<确切命令>` —— <期望看到什么>
2. `<确切命令>`
3. 重复 `<命令>` 直到输出出现 "<标志文字>"，或连续 3 次没有进展。

判定：
- PASS：<条件>
- FAIL：<条件>，附上 <最后一次某命令的输出>
- 已知、不算问题：<现象>

范围：
- 只做上面的步骤；<不要碰的东西>。
- 最多 <N> 轮 / <M> 分钟。
```

## 好的和坏的写法

| 坏 | 好 |
|---|---|
| "看看战斗有没有问题" | "跑 `RunDive 40 true` 到出现 `Combat ready.`，然后跑 `Occlusion`；输出不是 `Nothing covered.` 算 FAIL" |
| "检查数值是否合理" | "跑 `python tools/sim.py --seeds 50 --layer 1`，第 1 层平均回合数不在 4–7 之间算 FAIL，列出越界的种子" |
| "分析日志" | "在 `Player.log` 里找第一条 `Exception`，给出它前 20 行和堆栈顶 5 帧，说出触发它的命令" |
| 不写停止条件 | "连续 3 次 `RunDive` 输出相同就停，附最后一次 `Describe`" |

## 适合的任务类型

- **交互走查**：用一个命令工具驱动跑起来的程序（打包版、本地服务），一步步检查，截一两张图核对布局。
- **自检复跑**：修了一个问题后，把同一套检查重跑一遍，确认 PASS。
- **数值 / 模拟扫参**：跑一组参数或种子，汇总成表，标出越界项；脚本写到 scratch 目录。
- **日志排查**：在大日志里定位第一个异常和触发它的操作。
- **一致性检查**（`--mode read`）：配置和文档对不对得上、某个 API 的调用点是否都改了、引用的文件是否都存在。
